## Approved AC1 policy

The following recommendations were reviewed and approved by `simplysoup` on 2026-09-23:

1. **Source composition:** With no sidecar, preserve exact legacy behavior. With schema-v5 pool mode, each pool names complete, validated package IDs from the local library or configured Worldwall registry; duplicate IDs across sources are rejected. In non-adaptive mode, automatic selection considers the union of enabled pools and enabled scenes. In CR-0006 adaptive mode, retain the adaptive registry as the source of family/band candidates and use pool/rule state only as a filter; non-adaptive library entries do not silently become adaptive families. Manual selection may load any package explicitly known and fully validated by the configured library/registry.
2. **CR-0006 composition:** Compute the existing prospective temperature band/family using CR-0006 policy. Filter that family's precipitation variants in the existing appearance-preference order. Do not cross to another family/band or use V29 merely because a pool/rule rejected the selected variant. If no candidate remains, report no eligible candidate. Fresh same-family weather-variant attempts use the same filter. Do not persist family/band state for a rejected candidate; persist only after the scene transaction commits.
3. **Unknown inputs:** A configured time, weather, or temperature criterion requires a known value and does not match unknown data. An omitted criterion is unconstrained. Pool/rule edits do not start a weather request or add a selection trigger.
4. **No candidate:** Startup with no eligible candidate exits nonzero before presentation, with a bounded diagnostic such as `startup selection unavailable: no eligible scene`; do not print coordinates or raw weather details. Later triggers retain the resident scene; `next` reports a no-op reason. No path uses a hidden/ineligible fallback.
5. **Non-adaptive ranking:** Run the existing deterministic score/order over eligible candidates only. A designated fallback is selectable only when it is in the eligible set, never as a bypass around the filter.

The tested Firefox version is an observation for this host, not a cross-version support guarantee; packaging/version support remains to be documented and validated separately.
