## Outcome

The approved Open-Meteo provider is now wired to an explicit runtime
configuration without changing the renderer or selection ownership boundaries.
The configuration is:

```sh
WORLDWALL_WEATHER=open-meteo
WORLDWALL_WEATHER_LATITUDE=<decimal latitude>
WORLDWALL_WEATHER_LONGITUDE=<decimal longitude>
```

When `WORLDWALL_WEATHER` is unset, no provider, worker, or request is created.
When enabled, startup validates the provider and both coordinates before the
renderer starts, loads the XDG cache best-effort, starts one asynchronous
Open-Meteo refresh, and selects from the cache snapshot currently available.
The startup request is never awaited by Wayland or rendering.

Weather completion/deadline polling is driven by a separate one-second
low-frequency calloop timer, not the animation timer and not per-frame logic.
A completion updates the cache epoch/diagnostics only. It does not call the
selector, upload a scene, or alter the active scene. The active weather value
is only supplied to the existing startup snapshot boundary; late results do
not initiate another selection.
